# Codex Usage Reports

**Codex の Task ごと・ターンごとに、トークン使用量レポートを自動作成。** Task の累計、ターンごとの増分、観測されたモデルと推論の強度、サブエージェントの使用量を、コンパクトなローカルレポートで確認できます。

## 更新通知

各タスクの最初のプロンプトで、プラグインの更新とフックの信頼状態を確認します。更新後はターミナルで `codex` を起動し、`/hooks` で変更されたフックを確認して信頼してください。独立した通知フックは通常の更新後も信頼を維持できますが、**このバージョンの初回インストール時には通知フック自体の承認が必要です**。確認にはキャッシュを使い、作業を停止せず、モデルを呼び出さず、更新や信頼の付与を自動実行しません。

[詳細 / Details](../UPDATE_NOTICES.md).

## プロジェクトの exec アクティビティ

作業ディレクトリごとに追加の `codex exec` を確認し、フォアグラウンドで変更を監視できます。任意のランチャーは ephemeral 実行の開始・終了・使用量も記録します。更新した hooks を再承認して新しいタスクを開始すると、ツールの終了時に新しい実行を通知します。ランチャーの親情報とネイティブの子エージェント関係は区別され、使用量は親タスクに自動加算されません。[コマンドと対象範囲](../EXEC_ACTIVITY.md)。

## 各ターンの使用量を把握する

長い Task には、複数のターン、モデルの切り替え、サブエージェントの実行が含まれることがあります。セッション全体の合計だけでは、直近のターンでどれだけ増えたかはわかりません。Codex Usage Reports は、集計の範囲を分けて表示します。

| 知りたいこと | レポートに表示される情報 |
| --- | --- |
| この Task の累計使用量は？ | 選択した親 Task で観測された累計トークン数。 |
| このターンでどれだけ増えた？ | ネイティブのターン別カウンター、または同じソースの有効な累計カウンター間の差分。 |
| どのモデルと推論の強度で実行された？ | そのターンで観測された設定と、確認できた設定変更。 |
| サブエージェントの使用量は？ | 個別に集計したサブエージェントの小計と、データの取得状況。 |
| アカウントの利用枠はどれだけ残っている？ | 取得可能な場合に、ネイティブの利用枠の観測値を Task のトークン数と分けて表示。 |
| 後から確認できる？ | ローカルに保存される HTML、Markdown、JSON のレポート記録。 |

実行時に使用するのは Python 標準ライブラリのみです。使用量の計算に LLM を呼び出すことはなく、API キーも不要です。レポートを外部の分析サービスに送信することもありません。[Codex Run Budget](https://github.com/easyvibecoding/codex-run-budget) からレポート機能を切り出した、単独で動作するプロジェクトです。

## クイックスタート

Python 3.10 以上と、プラグインの hooks に対応したローカルの Codex 環境が必要です。インラインカードには、ローカルの可視化に対応したデスクトップ画面が必要です。CLI では保存済みのレポートを閲覧できます。ネイティブデータのスキーマはバージョンによって異なります。[互換性と検証](../../docs/VALIDATION.md)を参照してください。

### 1. プラグインをインストールする

```sh
codex plugin marketplace add easyvibecoding/codex-usage-reports
codex plugin add codex-usage-reports@codex-usage-reports
```

Codex でプラグインの hooks を確認して信頼し、**新しい Task を開始**してください。インストール済みの hooks は、ホスト環境の信頼設定とライフサイクルのルールに従って読み込まれます。公式の[プラグインガイド](https://learn.chatgpt.com/docs/plugins)と [hooks ガイド](https://learn.chatgpt.com/docs/hooks)を参照してください。

更新後は Codex CLI で `/hooks` を開き、変更されたプラグインの hooks を再確認して信頼してください。信頼は hook の定義にひも付きます。プラグインがインストール済みで有効でも、`modified` 状態の hooks は実行されません。アプリの再起動やスマートフォンからの Task 作成では信頼は付与されません。確認後、新しい Task を開始してください。

### 2. いつもどおりに作業する

普段どおり Codex に作業を依頼してください。Hook がターン開始時の基準値を記録し、最終回答の前にカードを 1 回作成するよう依頼します。対応する終了イベントを受信すると、レポート記録を保存します。自動レポートは初期設定で有効です。

`Stop` の後、ローカルの Python バックグラウンドプロセスが、そのターンのネイティブ `task_complete` 記録を確認します。走査範囲を制限し、最大 8 回、再試行期限は 25 秒です。モデルの呼び出しや Task の続行は行いません。ターンの完了境界を確認できた場合は、次のターンを含めず、書き込み済みの最終回答の使用量を反映した改訂版を別途保存します。根拠が不足する場合は保留中または一部取得済みの状態を維持します。自動レポートを無効にすると、それ以降の照合も停止します。

インラインカードは、最終回答の**前**に取得したスナップショットのままです。元の Stop JSON、HTML、Markdown レポートはすべて保持され、新たに取得する Task レポートでは公開済みの最新の改訂版が選ばれます。カードの HTML ファイルを上書きしても、既存カードの更新は保証できません。スマートフォンのリモート画面で行った A/B 実験では、Task を開き直しても元のカードは A のままで、新しい参照だけが B を表示しました。そのため、既存のインラインカードの自動置換は有効にしていません。[完了後の照合とプレビューの動作](../../docs/ARCHITECTURE.md#completion-reconciliation)を参照してください。

### 3. Task を確認する

付属の `usage-report` skill に、たとえば次のように依頼できます。

> この Task の使用量レポートを表示してください。ターンごとの使用量と、観測された設定も含めてください。

スタンドアロン CLI を使う場合は、リポジトリをクローンします。

```sh
git clone https://github.com/easyvibecoding/codex-usage-reports.git
cd codex-usage-reports
python3 plugins/codex-usage-reports/scripts/usage_reports.py auto-report status
python3 plugins/codex-usage-reports/scripts/usage_reports.py task "$TASK_ID" --format markdown
```

`TASK_ID` には、確認したい Task のネイティブ ID を設定してください。レポートの対象は、その Task に限定されます。HTML のエクスポート、設定、アンインストールについては、[詳しい使い方](../../docs/USAGE.md)を参照してください。

## 内容を確かめられるレポート

- **欠けたデータを明示。** カウンターのリセット、途中で切れた記録、設定の矛盾は、不完全または不明として扱います。
- **過去の設定を保持。** 現在のグローバルなモデル設定で、過去のターンの観測結果を置き換えません。
- **完了記録を照合。** 回数を制限したローカル処理で後から書き込まれたネイティブ記録を照合し、元の Stop JSON／HTML／Markdown レポートとインラインのスナップショットを保持します。
- **集計範囲を分離。** キャッシュ入力は入力の一部、推論出力は出力の一部です。サブエージェントの使用量とアカウントの利用枠も個別に表示します。
- **ローカルに保存。** レポートの状態データ内のネイティブ識別子はハッシュ化されます。非公開の表示名がローカルレポートに含まれる場合はあります。
- **軽量な hooks。** レポートのエラーによってツールの呼び出しを拒否したり、エージェントを停止したりすることはありません。
- **多言語カード。** 英語、繁体字中国語、簡体字中国語、日本語、韓国語、ドイツ語、フランス語、スペイン語、ポルトガル語に対応。README は 4 言語で提供しています。

## Codex Run Budget からの移行

2 つのプラグインはそれぞれ独立しています。予算制御のために元のプラグインを残す場合は、カードの重複を避けるため、元の自動レポートを無効にしてから本プラグインを有効にしてください。過去のデータベースを移行する必要はありません。[移行手順](../../docs/MIGRATION.md)。

## 制約

レポートは観測された使用量を示すもので、**請求書や正確な課金額ではありません**。利用枠はアカウント単位のため、トークンの合計から個々の Task に割り当てることはできません。サブエージェントの使用量の帰属は、取得できるネイティブの親子関係データに依存します。Hook の配信状況やネイティブスキーマは、Codex のバージョンによって変わる可能性があります。このプラグインは予算制限を設けず、作業を中断しません。

レポートにはプロジェクト名や利用傾向が含まれる場合があります。実際のレポートはローカルに保管し、公開 issue には合成テストデータのみを使用してください。[プライバシーとセキュリティ](../../SECURITY.md)。
