# Codex Usage Reports

**Codex の Task ごと・ターンごとに、トークン使用量レポートを自動作成。** Task の累計、ターンごとの増分、観測されたモデルと推論の強度、サブエージェントの使用量を、コンパクトなローカルレポートで確認できます。

## クイックスタート

Python 3.10 以上と、プラグインの hooks に対応したローカルの Codex 環境が必要です。インラインカードには、ローカルの可視化に対応したデスクトップ画面が必要です。CLI では保存済みのレポートを閲覧できます。ネイティブデータのスキーマはバージョンによって異なります。[互換性と検証](../../docs/VALIDATION.md)を参照してください。

### 1. プラグインをインストールする

```sh
codex plugin marketplace add easyvibecoding/codex-usage-reports
codex plugin add codex-usage-reports@codex-usage-reports
```

Codex でプラグインの hooks を確認して信頼し、**新しい Task を開始**してください。インストール済みの hooks は、ホスト環境の信頼設定とライフサイクルのルールに従って読み込まれます。公式の[プラグインガイド](https://learn.chatgpt.com/docs/plugins)と [hooks ガイド](https://learn.chatgpt.com/docs/hooks)を参照してください。

フック定義が変更された更新後は Codex CLI で `/hooks` を開き、新しい `SubagentStart` を含め、変更済みまたは未信頼と表示されたすべての定義を再確認して信頼してください。信頼は hook の定義にひも付きます。プラグインがインストール済みで有効でも、`modified` 状態の hooks は実行されません。アプリの再起動やスマートフォンからの Task 作成では信頼は付与されません。確認後、新しい Task を開始してください。

### 2. いつもどおりに作業する

普段どおり Codex に作業を依頼してください。対応するライフサイクルイベントが届くと、親 Task と各サブエージェントはそれぞれの Task／turn ID で基準値を記録し、最終回答の前にカードを作成して、個別のレポート記録を保存します。自動レポートは初期設定で有効です。実際の取得範囲は hook の配信とネイティブ記録によって異なります。

自動カードの指示は回答末尾のカードだけに適用されます。最終回答に完全一致、JSON のみ、コードのみ、または回答スキーマの指定がある場合は、プレビューと参照の両方を省略します。生成するファイルの形式はこの判定に影響しません。カードを追加できる場合、親 Task とサブエージェントは自分の参照だけを変更せず独立した行に付け、他のエージェントの参照は転送しません。[自動レポート](../../docs/USAGE.md#automatic-reports)を参照してください。

`Stop` または `SubagentStop` の後、ローカルの Python バックグラウンドプロセスが、その Task とターンのネイティブ `task_complete` 記録を確認します。走査範囲を制限し、最大 8 回、再試行期限は 25 秒です。モデルの呼び出しや Task の続行は行いません。ターンの完了境界を確認できた場合は、次のターンを含めず、書き込み済みの最終回答の使用量を反映した改訂版を別途保存します。根拠が不足する場合は保留中または一部取得済みの状態を維持します。自動レポートを無効にすると、それ以降の照合も停止します。

インラインカードは、最終回答の**前**に取得したスナップショットのままです。終了イベント時点の元の JSON、HTML、Markdown レポートはすべて保持され、新たに取得する Task レポートでは公開済みの最新の改訂版が選ばれます。カードの HTML ファイルを上書きしても、既存カードの更新は保証できません。スマートフォンのリモート画面で行った A/B 実験では、Task を開き直しても元のカードは A のままで、新しい参照だけが B を表示しました。そのため、既存のインラインカードの自動置換は有効にしていません。[完了後の照合とプレビューの動作](../../docs/ARCHITECTURE.md#completion-reconciliation)を参照してください。

### 3. Task を確認する

付属の `usage-report` skill に、たとえば次のように依頼できます。

> この Task の使用量レポートを表示してください。ターンごとの使用量と、観測された設定も含めてください。

スタンドアロン CLI を使う場合は、リポジトリをクローンします。

```sh
git clone https://github.com/easyvibecoding/codex-usage-reports.git
cd codex-usage-reports
python3 plugins/codex-usage-reports/scripts/usage_reports.py auto-report status
python3 plugins/codex-usage-reports/scripts/usage_reports.py task "$TASK_ID" --format markdown
```

`TASK_ID` には、確認したい親 Task またはサブエージェントのネイティブ ID を設定してください。選択した Task のネイティブカウンターと記録はその Task 自身のものです。検証された子孫の使用量は別の小計として表示されます。HTML のエクスポート、設定、アンインストールについては、[詳しい使い方](../../docs/USAGE.md)を参照してください。

## 各ターンの使用量を把握する

長い Task には、複数のターン、モデルの切り替え、サブエージェントの実行が含まれることがあります。セッション全体の合計だけでは、直近のターンでどれだけ増えたかはわかりません。Codex Usage Reports は、集計の範囲を分けて表示します。

| 知りたいこと | レポートに表示される情報 |
| --- | --- |
| この Task の累計使用量は？ | 選択した親 Task またはサブエージェント自身で観測された累計トークン数。 |
| このターンでどれだけ増えた？ | ネイティブのターン別カウンター、または同じソースの有効な累計カウンター間の差分。 |
| どのモデルと推論の強度で実行された？ | そのターンで観測された設定と、確認できた設定変更。 |
| 子孫エージェントの使用量は？ | ネイティブの親子関係で確認できた別の小計と、データの取得状況。選択した Task のネイティブカウンターには加えません。 |
| アカウントの利用枠はどれだけ残っている？ | 取得可能な場合に、ネイティブの利用枠の観測値を Task のトークン数と分けて表示。 |
| 後から確認できる？ | ローカルに保存される HTML、Markdown、JSON のレポート記録。 |

サブエージェントのカードと記録は、そのエージェント自身の使用量を示します。親 Task では、検証できたネイティブの親子関係に基づく子孫の小計を別に示します。親の子孫行と子自身のカードやレポートには同じハッシュ化された `@` 識別子が表示され、同名のエージェントも対応付けられます。観測時点や取得範囲は異なる場合があり、hook、カウンター、親子関係の証拠が欠けると一部取得済みまたは不明と表示します。子の使用量を親のネイティブカウンターに混ぜません。

実行時に使用するのは Python 標準ライブラリのみです。使用量の計算に LLM を呼び出すことはなく、API キーも不要です。レポートを外部の分析サービスに送信することもありません。[Codex Run Budget](https://github.com/easyvibecoding/codex-run-budget) からレポート機能を切り出した、単独で動作するプロジェクトです。

## 内容を確かめられるレポート

- **欠けたデータを明示。** カウンターのリセット、途中で切れた記録、設定の矛盾は、不完全または不明として扱います。
- **過去の設定を保持。** 現在のグローバルなモデル設定で、過去のターンの観測結果を置き換えません。
- **完了記録を照合。** 回数を制限したローカル処理で後から書き込まれたネイティブ記録を照合し、終了イベント時点の元の JSON／HTML／Markdown レポートとインラインのスナップショットを保持します。
- **集計範囲を分離。** キャッシュ入力は入力の一部、推論出力は出力の一部です。サブエージェントの使用量とアカウントの利用枠も個別に表示します。
- **キャッシュ読み取り率。** カードと保存済みレポートには、観測された入力に占めるキャッシュ入力の割合が表示されます。入力が欠落またはゼロなら利用不可のままで、公式のキャッシュミス診断ではありません。
- **ローカルに保存。** レポートの状態データ内のネイティブ識別子はハッシュ化されます。非公開の表示名がローカルレポートに含まれる場合はあります。
- **軽量な hooks。** レポートのエラーによってツールの呼び出しを拒否したり、エージェントを停止したりすることはありません。
- **多言語カード。** 英語、繁体字中国語、簡体字中国語、日本語、韓国語、ドイツ語、フランス語、スペイン語、ポルトガル語に対応。README は 4 言語で提供しています。

## プロジェクトの exec アクティビティ

作業ディレクトリごとに追加の `codex exec` を確認し、フォアグラウンドで変更を監視できます。任意のランチャーは ephemeral 実行の開始・終了・使用量も記録します。関連する hooks を承認して新しいタスクを開始すると、ツールの終了時に新しい実行を通知します。ランチャーの親情報とネイティブの子エージェント関係は区別され、使用量は親タスクに自動加算されません。[コマンドと対象範囲](../EXEC_ACTIVITY.md)。

## 自動更新と初回の承認

初回インストール後、CLI の `codex` → `/hooks` で固定エントリーを確認して信頼してください。通常のランタイムと CLI の更新ではフック定義が変わらず、再承認は不要です。これは同じ発行者が今後署名するプログラムの実行を許可するものです。既定ではプロンプト送信時に最大6時間に1回、バックグラウンドで確認し、署名とファイルのハッシュが一致した更新だけを有効にします。新しいタスクには検証済みバージョンを表示し、進行中のタスクは元のバージョンを保持します。

新しいフック、エントリーや鍵の変更、プラグイン／skill 構造の変更には、通常の更新と変更フックの確認が必要です。Codex の信頼記録は書き換えません。インストール済みプラグイン内で `python3 scripts/publisher_updates.py status` を実行すると実際のバージョンを確認できます。`off`、`on`、`update`、`rollback` で無効化、有効化、手動更新、ロールバックができます。Plugins 画面は元のパッケージバージョンを表示する場合があります。[更新の仕組みと操作](../SIGNED_UPDATES.md) · [信頼の通知](../UPDATE_NOTICES.md)。

インストール済みプラグインのバージョンとネイティブ hook の信頼状態を手動で確認するには、`python3 scripts/usage_reports.py updates check --refresh --cwd "$PROJECT_DIR"` を実行します。この結果は現在有効な署名付きランタイムのバージョンとは別の範囲です。

## 対になるプロジェクトの変更レビュー

Codex Run Budget のプロジェクト間レビューは**実験的な任意機能**です。利用者が 2 つのローカル Codex プロジェクトのルートを指定して名前付きペアを登録し、全体スイッチと各ペアのスイッチを有効にします。1 つのプロジェクトを複数のペアに含められます。このリポジトリのペアでは、有効な Stop hook が新しいリモート `main` の範囲を検出すると、相手のプロジェクトに読み取り専用のレビュー Task を作るよう要求できます。2 つの Task はそのペア内で一対一に紐付けられ、以後の Stop 要約は同じ相手に送られます。受信による反響は抑制されます。[この 2 つのリポジトリのレビュールール](../CROSS_REPO_REVIEW.md)に従い、証拠に基づいて変更をそろえる必要があるか判断します。ペアと任意の手動リモート走査は Run Budget が管理します。Usage Reports は独立したレポート専用プラグインです。[設定とスイッチ](https://github.com/easyvibecoding/codex-run-budget/blob/main/docs/PAIRED_REVIEW_AUTOMATION.md)。

## Codex Run Budget からの移行

2 つのプラグインはそれぞれ独立しています。予算制御のために元のプラグインを残す場合は、カードの重複を避けるため、元の自動レポートを無効にしてから本プラグインを有効にしてください。過去のデータベースを移行する必要はありません。[移行手順](../../docs/MIGRATION.md)。

## 制約

レポートは観測された使用量を示すもので、**請求書や正確な課金額ではありません**。利用枠はアカウント単位のため、トークンの合計から個々の Task に割り当てることはできません。サブエージェントの使用量の帰属は、取得できるネイティブの親子関係データに依存します。Hook の配信状況やネイティブスキーマは、Codex のバージョンによって変わる可能性があります。このプラグインは予算制限を設けず、作業を中断しません。

レポートにはプロジェクト名や利用傾向が含まれる場合があります。実際のレポートはローカルに保管し、公開 issue には合成テストデータのみを使用してください。[プライバシーとセキュリティ](../../SECURITY.md)。
